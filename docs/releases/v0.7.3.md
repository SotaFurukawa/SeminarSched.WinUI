# v0.7.3 (beta)

Status: Draft Release。v0.7.2公開後のユーザー報告「やはり既定の倍の時間をかけても無理でした。また、2倍の時間をかけてしまうと、時間割が生成されないので、何も生み出していないことになります。その場合、警告を出して、無理やり作ったことを明示する。また、アルゴリズムについても停止しない原因が他にもあるのではないか。また、配置できない原因がある場合はその警告を出す」（checkpoint 94）への対応。bug fixのためNext Version Ruleの既定に従いv0.7.3とした。

## ハイライト

- 未配置のコマが1件でも残った状態を、これまで他の完成ケースと同じ緑色の「作成しました」表示で埋もれさせていたのを、はっきり分かる警告表示（黄色・タイトル「未配置がN件残ったまま作成しました（要確認）」）に変更した。
- 未配置が残った理由をベストエフォートで診断し、可能な範囲で具体的に伝えるようにした。担当講師優先度が「5（固定）」に設定されている生徒で、その講師の空きコマ不足が原因と考えられる場合や、対応できる講師が構造的に1人もいない（どれだけ時間をかけても解決しない）場合は、それぞれ別の理由として案内する。
- CP-SATの「粘り強く試行を繰り返す」探索（grinding戦略）が、1回の試行の持ち時間内にfeasible解にすら届かず失敗し続けるケースへの対応として、失敗するたびに次回の試行の持ち時間を自動的に伸ばすようにした。問題の規模に対して初期値（60秒）が短すぎるケースで、いつまでも同じ短い持ち時間で失敗を繰り返すだけになる状況を緩和する。

## 主な変更点

### 未配置が残った場合の警告表示
- `OptimizationPage`の完了時メッセージを、`未配置0件`と`1件以上`で分岐するようにした。0件なら従来通り緑色の「時間割を作成しました」。1件以上なら黄色（Warning）で「未配置がN件残ったまま作成しました（要確認）」と表示する。
- 未配置件数自体はメッセージ本文に以前から含まれていたが、InfoBar全体の色・タイトルが常に「成功」表示だったため、件数を読み飛ばすと問題が無いように見えてしまっていた。

### 未配置の原因診断（担当講師優先度5・対応可能講師なし）
- `SqliteScheduleRunService`に、未配置のまま残った受講希望ごとに原因をベストエフォートで分類する処理を追加した。
  - 候補コマが1件も無い（講師の資格・出勤可否の時点で構造的に配置不可能。時間をかけても解決しない）→「対応できる講師の候補コマが構造的に見つかりませんでした」
  - 担当講師優先度5により候補が通常担当講師（＋希望講師）へ絞り込まれ、かつ絞り込み後も未配置が残った（＝その講師の空きコマ不足が理由の可能性が高い）→「担当講師優先度が5（固定）の生徒で、指定講師の空きコマ不足が原因の可能性があります」
- `ScheduleRunSummary`に`UnassignedDueToRegularTeacherPriority`・`UnassignedWithNoQualifiedTeacher`の2つのカウントを追加し、⑤画面の完了メッセージへ該当する案内文を自動的に追加するようにした。どちらにも当てはまらない残りは、他の生徒・講師との競合など単一の原因に帰属させられないケースとして区別していない。

### grinding戦略の試行持ち時間の自動延伸
- `GrindingStrategyBase`（`GrindingNeighborhoodRepairStrategy`/`GrindingFinalPolishingStrategy`が使う、持ち時間を使い切るまで独立した試行を繰り返す仕組み）の1回あたりの試行持ち時間は、従来は最短10秒・最大60秒の固定範囲だった。
- 試行がfeasible解にすら届かず失敗した場合（CP-SATが`Unknown`/`Infeasible`を返した場合）、次回以降の試行の持ち時間を倍にするようにした（このステージの持ち時間全体は超えない）。モデル構築・presolveのオーバーヘッドに対して初期値が短すぎる大きな問題規模で、同じ短い持ち時間のまま無意味に失敗を繰り返し続ける状況を緩和する狙い。

## 既知の未実装・保留

- 出力設定の表示項目ON/OFF・ロゴ画像・1ページの日数/講師列数・生徒別改ページ方式は引き続き未実装。
- 授業間隔の均等化・同一科目の連続抑制は、CP-SATの目的関数への近似的なソフト制約であり、常に理想的な結果を保証するものではない（v0.6.0から変更なし）。
- 未配置の原因診断は、担当講師優先度5・対応可能講師なしの2パターンのみ。それ以外（他の生徒・講師との競合、探索時間不足等）は個別の原因を特定せず、件数の差分でしか分からない。生徒名・科目名まで含めた詳細な内訳表示は今回は行っていない。
- 品質プロファイル（`OptimizationProfileCatalog`）自体のさらなる見直しは保留中（ユーザーからの明示的な要望あり、実装するまで毎回案内する）。
