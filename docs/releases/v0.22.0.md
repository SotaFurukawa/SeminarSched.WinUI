# v0.22.0 (beta)

Status: Draft Release。生徒・講師・科目の登録方式を刷新する新機能のためminorを上げてv0.22.0とした。

## 変更内容

- **生徒・講師・科目タブを行内編集方式に刷新**: 従来は一覧の上に常時表示される入力フォームへ
  入力して保存する方式だったが、検索欄の右の「追加」ボタンで一覧の最下部に新しい編集行を
  表示し、その場で入力して保存する方式に変更した。既存の行は、一覧の行にカーソルを合わせたときに
  表示される「変更」ボタンで、同じように行内で編集できる。一覧がより広く使えるようになり、
  入力と一覧が同じ場所に統合された。
  - 一度に編集できる行は1つだけ（追加・変更どちらを押しても、編集中だった行は閉じる）。
  - 生徒ID・講師IDは保存するまで確定しない採番予定のIDとして編集行に表示される（従来通り
    自動採番、変更不可）。
  - 「在籍中」「有効」のチェックボックスは、従来の即時保存ではなく、他の項目と同様に保存
    ボタンを押したときにまとめて保存される方式に統一した。

## 検証について

生徒・講師・科目それぞれで、既存の実データ（テストプロジェクト、77名の生徒・22名の講師・
27件の科目を含む）を使い、実機（dev-run）で実際に操作して確認した：
①既存行の変更→保存→一覧へ正しく反映、②追加ボタン→一覧最下部へ自動スクロール→新規入力→
保存→新しいIDで一覧へ追加、③科目タブの校種ComboBox（編集可能）を含む全フィールドの保存、
④ホバーで「変更」ボタンが表示される挙動。

開発中に2点の不具合を見つけて修正した：保存直後に編集行が再び開いてしまう不具合（保存成功後の
一覧再読み込みが、保存したばかりの行を「編集中だった行」と誤認識していたため）、および
追加ボタンを押しても一覧が自動的に最下部までスクロールしない不具合（ListView自身ではなく、
ページ全体を包む外側のスクロール領域を動かす必要があった）。

既存の全テスト（Architecture/Domain/Application/Optimization/Infrastructure、計252件）が
すべて通過することも確認済み。
