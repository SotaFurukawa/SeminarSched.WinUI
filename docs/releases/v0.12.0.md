# v0.12.0 (beta)

Status: Draft Release。checkpoint 110の続きで指示された6項目のうち、今回のcheckpoint 111で対応
できる分（可用性の手動編集の全面刷新、出勤出席可否の値の見直し、体験生の可視化）を反映した。
データモデル（`AvailabilityLevel`のCHECK制約）を変更するためminorを上げてv0.12.0とした。

## ハイライト

- ③アンケート取込「可用性の手動編集」を、複数選択・一括適用の一覧UIから、生徒/講師を1名選んで
  カレンダーで確認・編集するUIへ全面刷新した。開講日ごとにコマの帯（チェックボックス＋コマ名）が
  並び、緑=参加可能・赤=参加不可で表示し、チェックのたびに保存操作なしで即座にDBへ反映する。
  複数日付・複数コマへの一括適用機能は撤廃した。
- 出勤出席可能日の値から「優先」（レベル2）を廃止し、「不可」「可」の2値のみとした。既存プロジェクト
  を開いた際、レベル2のデータは自動的にレベル1（可）へ変換される。
- ③アンケート取込で、体験生として自動登録された生徒に「[体験生]」の表示を追加した（生徒選択欄・
  受講希望一覧の両方）。

## 検討したが今回は見送った項目

- 時間割編集のロック（`IsLocked`）について、「自動作成で動かないのはロックのおかげか」というご質問
  への回答: 実際に自動作成時の再配置から保護しているのは`IsManual`（手動配置）フラグであり、
  `IsLocked`は手動編集画面でのドラッグ操作を追加で禁止するための別概念だった。ユーザー確認の結果、
  現状維持（`IsLocked`はそのまま残す）とした。
- 集団授業に「担当講師（任意）」を割り当て、個別授業をブロックし全体時間割に「集団」表示する機能は、
  ドメインモデル・ソルバー制約・Excel/PDF帳票の3か所にまたがる新機能のため、今回のバージョンでは
  スコープ外とし、次のバージョンで実装する。

詳細は[機能同等性台帳](../FEATURE_PARITY.md)を参照。

このversionのGitHub ReleaseはDraftとして作成する。
