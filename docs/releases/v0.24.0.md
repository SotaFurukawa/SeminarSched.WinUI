# v0.24.0 (beta)

Status: Draft Release。生徒・講師の氏名を姓・名に分けて保存する仕様変更のためminorを上げてv0.24.0とした。

## 変更内容

- **生徒・講師の氏名を「姓」「名」に分けて保存するようにした**: 出力（Excel・PDF帳票）では
  従来から基本的に苗字のみを使う運用だったため、従来の単一の氏名欄をやめ、`FamilyName`（姓、
  必須）・`GivenName`（名、任意）を正式なデータ項目とした。プロジェクト設定の生徒・講師タブは、
  編集欄・一覧表示列ともに「姓」「名」の2つに分割した（講師指導可能科目マトリクス・通常授業
  担当設定・受講希望一覧などの氏名表示もすべて姓名を結合した表示に追従）。
- **既存プロジェクトは自動で移行される**: 既存の`.jukuschedule`を開いた時点で、これまでの単一
  氏名欄を最初の半角スペースで姓・名に自動分割して埋める（スペースが無い場合は全体を姓とし、
  名は空欄）。移行は他の加法的スキーマ変更と同じ仕組み（ALTER TABLEとトランザクション内の
  自己修復バックフィル）で行われ、失敗時は元データを壊さない。
- **共通名簿Excel（生徒・講師_基本情報.xlsx）は「姓（必須）」「名」「氏名（確認）」の3列を
  出力するようにした**。再取込み時は新しい「姓」列を優先して読み、無ければ従来通り「氏名」列
  を分割して読む（後方互換のため、過去にエクスポート済みの古いExcelファイルも壊さず使える）。
- 旧来の単一氏名列（`Name`）はデータベース内に残し、保存のたびに姓名から再計算して書き込み
  続けている。時間割の帳票出力（姓のみ表示を含む）など、この列を直接参照している他の箇所は
  今回変更していない。

## 検証について

既存の全テスト（計252件）がすべて通過することを確認済み。加えて、実際のプロジェクトデータ
（実機・dev-run）で、①既存プロジェクトを開いた際に姓・名が正しく自動分割されて一覧へ表示
されること、②生徒一覧で既存行の「変更」から姓・名を個別に編集し保存→一覧へ正しく反映される
ことを確認した。共通名簿Excelの書き出し・再取込みは自動テスト（`SharedRosterStoreTests`等）
でカバーされている。

詳細は[docs/CODEX_HANDOFF.md](../CODEX_HANDOFF.md)を参照。
