# v1.7.1

Status: Release

## 変更内容

ユーザー要望「このプロダクトキーはできればいくつも出せるような仕様にしてほしい」への対応。

以前は年度（または完全版/master）という値から決定的にキーを計算するだけだったため、同じ年度には
常に同じキーしか生成できなかった（校舎ごとに別々のキーを配る、といったことができなかった）。
検証には関与しない2バイトの乱数「salt」をチェックサムの対象へ加え、`ProductKeyService.
GenerateKey`を呼ぶたび（saltを明示指定しない限り）自動的に異なるキーを生成するようにした。

`tools/SeminarSched.ProductKeyTool`を同じ引数（年度やmaster）で複数回実行するだけで、見た目の
異なる複数の有効なキーを発行できる。校舎ごとに別々のキーを配りたい場合は、必要な回数だけ実行
すればよい。

**既に配布済みのキーは、この変更後も引き続き有効。** 新形式（16進16桁、4グループ）と旧形式
（16進12桁、3グループ、saltなし）の両方を受け付けるようにしたため、過去に発行したキーを
失効させない。

詳細は[ADR 0006のAmendment（v1.7.1）](../adr/0006-product-key-licensing.md)参照。

## 検証について

- `dotnet build`成功（警告・エラー0件）。
- 既存の全テスト、合計290件がすべて通過することを確認済み（新規2件を含む）。新規テストは、
  同じ年度でも異なるsaltなら異なるキーになり両方とも正しく検証できること、既に配布済みの旧形式
  キー（本セッション中に実際に生成した`FD98-3C5A-E685`）が引き続き有効であることを検証している。
