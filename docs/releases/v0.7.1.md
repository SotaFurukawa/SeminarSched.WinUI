# v0.7.1 (beta)

Status: Draft Release。v0.7.0公開後、実際に使ってみたユーザーからの報告「CPUの制限をしたせいか、最高品質だと2時間かけても終了しませんでした。PCの性能に合わせた計算の複雑さにするようにしてもらえますか」（checkpoint 92）への対応。bug fixのためNext Version Ruleの既定に従いv0.7.1とした。

## ハイライト

- ⑤時間割自動作成のCPU抑制方式を、OS側のハード上限（Job Object CPU rate control）からプロセス優先度の引き下げへ変更した。ハード上限は他の作業が何も動いていないときでも探索を頭打ちにしてしまい、本来数十分で終わるはずの探索が、名目時間の2倍まで許容する延長機構を使い切っても終わらない直接の原因になっていた。優先度を下げる方式なら、PCが空いていれば探索は遠慮なく全力で走り、他の作業と競合したときだけ道を譲る。
- CP-SATの並列探索ワーカー数の上限を、論理コアの1/3から1/2へ戻した。ハード上限の撤去でCPU専有の抑制は優先度側が担うため、ワーカー数側をそこまで絞る必要がなくなった。

## 主な変更点

### CPU抑制方式の見直し（ProcessResourceLimiter）
- v0.6.1・v0.7.0にかけて、Windows Job ObjectのCPU rate control（`JOB_OBJECT_CPU_RATE_CONTROL_HARD_CAP`）でプロセス全体のCPU使用率を35%へハード制限していた。この方式は、たとえ他のアプリが何もCPUを必要としていないアイドル状態でも、上限に達すると探索スレッドを問答無用で一時停止させる仕様であることが判明した。
- そのためユーザーが他の作業をしていない間も探索が上限で頭打ちになり続け、「最高品質だと2時間かけても終了しない」という報告につながった（最高品質の名目60分＋延長60分＝最大2時間の枠を、本来不要なはずの足止めで使い切ってしまっていた）。
- ハード上限を撤去し、`Process.PriorityClass`を`BelowNormal`へ下げる方式に置き換えた。優先度を下げるだけであれば、Windowsのスケジューラは実際に他のスレッドがCPUを必要としている「競合時」にだけ道を譲らせ、PCが空いていれば通常速度で走らせる。「⑤の実行中はパソコンが重くなる」という元の懸念には引き続き対応しつつ、アイドル時間を無駄にする副作用を取り除いた。
- 「CPU使用率を制限しない（フルパワーで実行）」チェックボックスの説明文も、新しい挙動（優先度を下げる方式）に合わせて更新した。

### CP-SAT並列探索ワーカー数の見直し
- `CpSatScheduleSolver.ResolvedAutoSearchWorkers`の上限を、v0.7.0時点の「論理コアの1/3（下限2）」から、v0.6.1時点の「論理コアの1/2（下限2）」へ戻した。
- CPU抑制の主な役割をプロセス優先度側に移したため、ワーカー数側まで大きく絞る必要がなくなった。ワーカー数を絞りすぎると、探索の並列度が下がり解の発見自体が遅くなる（＝重い問題ほど余計に時間がかかる）ため、両者を過剰に重ねないようにした。

## 既知の未実装・保留

- 出力設定の表示項目ON/OFF・ロゴ画像・1ページの日数/講師列数・生徒別改ページ方式は引き続き未実装。
- 授業間隔の均等化・同一科目の連続抑制は、CP-SATの目的関数への近似的なソフト制約であり、常に理想的な結果を保証するものではない（v0.6.0から変更なし）。
- 「PCの性能に合わせた計算の複雑さにする」という要望のうち、検出したハードウェア性能（`SystemRequirements`）に応じて品質プロファイル自体の構成（strategy数・近傍サイズ等）を自動選択する部分は未着手。今回は「アイドル時間を無駄にする副作用の除去」による速度改善にとどまる。実機での改善状況を見たうえで、必要であれば追加対応を検討する。
