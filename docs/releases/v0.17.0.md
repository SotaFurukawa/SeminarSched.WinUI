# v0.17.0 (beta)

Status: Draft Release。新機能のためminorを上げ、patchを0へ戻してv0.17.0とした。

## 新機能: ⑤時間割自動作成でも探索方針の優先度をその回だけ変更できるように

- これまで探索方針（優先度）の並び替えは「①設定」の「スケジュール設定」タブ（プロジェクトの
  既定値）でのみ可能だった。「⑤時間割自動作成」の「この回だけ探索の方針を変更する」にも同じ
  並び替えUI（行にカーソルを合わせると表示される▲▼、「考慮しない」以外を選ぶと自動的に一番上へ
  移動）を追加し、プロジェクトの既定値を変更せずに、その回の自動作成だけ優先順位を一時的に
  変更できるようにした。
- 並び替えUIのロジック（`SchedulingPolicyRowsController`）と、方針↔行の変換ロジック
  （`SchedulingPolicyRowViewModel.BuildRows`/`BuildPolicy`）を両画面で共有する形に整理した。

## 不具合修正: 考慮する方針を2つ以上設定すると並び替えが無限ループしてバグる

- ユーザー報告「考慮するものが2つ発生した場合、考慮するものは上に置くという指示がループして
  おり、2つ以上のものを配置するとバグる」に対応した。
- 原因: 並び替え後にコンテナを再構築する処理（`ItemsSource`の張り直し）が全行の`Loaded`を
  再発火させ、それが「考慮しない」以外の値を持つ行すべてで`SelectionChanged`を
  （ユーザー操作なしに）再トリガーしていた。2つ目の方針を先頭へ昇格させた際の再構築が、
  まだ先頭ではない1つ目の方針の`SelectionChanged`を誘発し、それがまた昇格→再構築→…と
  無限ループしていた。
- 修正: `SelectionChanged`で、新しい選択値が既存の保存済み値と同じ場合（＝実際の変更ではなく
  再同期によるものと判断できる場合）は何もしないようにした。この修正により、既存の「①設定」
  画面・新設の「⑤時間割自動作成」画面の両方でループが解消されたことを実機で確認した
  （3つの方針を連続して非デフォルト値に変更しても、正しく最新の変更が先頭に来て安定する）。

詳細は[docs/CODEX_HANDOFF.md](../CODEX_HANDOFF.md)を参照。
