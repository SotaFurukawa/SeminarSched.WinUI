# v0.11.0 (beta)

Status: Draft Release。ユーザー要望「品質プロファイルのリバランスを実装しましょうか。CPUのスコア表
みたいなのがあるはずなので、そのスコアを確認し（もしくはアプリ内のテストを自動的に動かしてみる
ことで）、そのスコアの閾値を設定することで、スコアを上回っていたら多めの負荷、下回っていたらあまり
負荷はかけないようにする。このスコアはアプリ内のテストをする場合、毎回やるものではなくて、初めて
自動作成する際に、一度だけ調べることにする。こちらも5段階くらい用意しておいてください」
（checkpoint 108）への対応。新機能のためNext Version Ruleの既定に従いv0.11.0とした。

長らく保留していた「品質プロファイル（`OptimizationProfileCatalog`）自体のさらなる見直し」に、
この形で対応した。

## ハイライト

- ⑤時間割自動作成を初めて実行するときに、そのパソコンの実際の性能を一度だけ自動計測するように
  なった（固定・決定的な架空の問題を実際に解かせ、かかった時間を測る。実データは一切使わない）。
  一度計測した結果はパソコンごとに記憶され、2回目以降の実行では再計測しない。
- 計測結果は5段階（非常に控えめ〜非常に高め）に分類され、その段階に応じて自動作成の並列度（CPU
  負荷）を調整する。性能が高いパソコンほど多めの負荷をかけて速く、控えめなパソコンほど負荷を
  抑えて他の作業への影響を減らす。
- 初回計測中は、⑤画面に「このパソコンの性能を測定しています」という案内を表示する（最大20秒
  程度）。
- 「アプリ情報」画面に、計測済みの判定結果と、パソコンを買い替えた場合などに使える「再測定する」
  ボタンを追加した。

## 主な変更点

- 新設`HardwareBenchmark`（`SeminarSched.Optimization.Diagnostics`）が、CP-SATで実際に合成問題を
  解かせ、かかった時間を5段階の`HardwareTier`へ分類する。
- `AppSettings`に`HardwareTier`（機体ごとの設定、プロジェクトファイルとは無関係）を追加し、
  `OptimizationRunState`が初回実行時にだけ計測・保存し、以降は再利用する。
- `CpSatScheduleSolver.ResolvedAutoSearchWorkers`（並列探索ワーカー数の上限）を、tierに応じた
  割合（25%〜85%）へ拡張した。標準的な性能（Standard）の場合は従来と同じ挙動（論理コアの半分）
  のため、既存プロジェクトの動作は変わらない。

## 既知の未実装・保留

- 計測の閾値（0.75秒/1.5秒/3.0秒/6.0秒）は、この開発機（16論理プロセッサ）1台の実測からの類推で
  あり、実際に様々な性能のパソコンで検証できていない。特に非力なパソコンでの判定結果・体感速度に
  ついては、実機でのご確認・フィードバックをお願いしたい。必要に応じて閾値を調整する。
- 品質プロファイル自体の時間配分（各品質レベルの秒数設定）は今回変更していない。今回はCPU負荷
  （並列度）の調整のみ。
