# v1.5.5

Status: Release

## 変更内容

ユーザー報告「基本情報xlsxを反映すると通常授業の中身が明らかに変わる／全く異なる（生徒・講師・
科目は完璧に一致する）」の原因究明と修正。

v1.3.0で通常授業担当設定（RegularLessonProfile）の一意キーへ通常担当講師IDを加え、同じ生徒・
科目でも担当講師が異なれば複数行を許すようにしたが、反映（インポート）処理はUPSERTのみで
DELETEを一切行わない設計のため、Excel側である生徒・科目の通常担当講師を別の講師へ変更して
反映しても、変更前の（生徒,科目,旧担当講師）の組み合わせの行は一意キーが一致せず削除されずに
残り、新しい（生徒,科目,新担当講師）の行が別途追加されるだけだった。担当講師の変更を反映の
たびに繰り返すと古い行が際限なく蓄積し、通常授業の内容が実際のExcelの内容とはかけ離れていく
不具合だった（反映を重ねてきた実運用ファイルで顕在化）。

`UpsertRegularLessonsAsync`を、生徒・科目ごとに今回のファイルに含まれる通常担当講師の集合
（講師未定＝NULLも1つの値として扱う）を求め、既存行のうちその集合に無いものを先に削除してから
ファイルの内容を反映する方式へ修正した。あわせて、SQLiteのUNIQUE制約はNULL同士を一致させない
ため通常担当講師未定の行がON CONFLICTで重複挿入されうる別の潜在的な不具合も、既存行をId付きで
取得して明示的にUPDATE/INSERTを振り分ける方式で修正した。

詳細は[ADR 0009のAmendment（v1.5.5）](../adr/0009-regular-lesson-profile-allows-duplicates.md)
を参照。

## 実運用データの自己修復について

既にこの不具合で蓄積してしまった古い（幽霊）行は、本バージョンへ更新したうえで現在お使いの
基本情報xlsxをもう一度「反映」すれば、ファイルに存在しない組み合わせの行が自動的に削除され、
自己修復される。別途クリーンアップツールの実行は不要。
