# v0.7.4 (beta)

Status: Draft Release。ユーザー要望「担当する生徒の人数（既定1対2）を1対3・1対4等へ変更できるようにしたい」「一日当たりの講師人数・講師ごとのコマ数の偏り・生徒の授業日・1コマあたりの生徒対応人数・時間帯・同時に使える座席数を自由に選択できるようにしたい」（checkpoint 95）への対応。ユーザーから明示的に「v0.7.4として作り、ドラフトリリースしてください」との指示があったため、Next Version Ruleの既定（新機能はminor bump）ではなくこのversion番号を使用した。

## ハイライト

- 1人の講師が同時に担当できる生徒数（既定1対2）を、プロジェクトごとに1〜10の範囲で変更できるようにした。新規プロジェクト作成時に選択でき、後から「①設定」の「スケジュール設定」タブでも変更できる。
- 自動作成の探索方針として、6つの新しい設定項目（①一日当たりの講師人数、②講師ごとのコマ数の偏り、③生徒の授業日、④1コマあたりの生徒対応人数、⑤時間帯、⑥同時に使える座席数）を追加した。プロジェクトの既定値として保存でき、⑤時間割自動作成の画面でその回だけ一時的に変更することもできる。
- 既定はすべて「考慮しない」。③（生徒の授業日）・④（1コマあたりの生徒対応人数）は、これまで常時ONだった機能（日程分散・ペア優遇）をトグル化したものなので、既定を「考慮しない」にすると既存プロジェクトでもこの2つの挙動が既定でOFFになる（ユーザーに確認の上での仕様）。

## 主な変更点

### 担当する生徒の人数（1対N）の設定化
- `SchedulingPolicy.MaxStudentsPerTeacher`（既定2、範囲1〜10）として、プロジェクトのSQLiteへ保存できるようにした。
- CP-SATのハード容量制約（`CpSatScheduleSolver`）・解の検証（`ScheduleSolutionValidator`）・手動配置時の容量チェック（`SqliteFixedLessonService`、警告文言も動的に「N人」表示へ）のすべてで、これまで固定だった「2」をこの設定値へ一般化した。
- 新規プロジェクト作成画面（`HomePage`）に入力欄を追加し、作成直後にプロジェクトへ保存する。

### 自動作成の探索方針6項目の追加
- `SchedulingPolicy`に6つの方針設定を追加し、`CpSatScheduleSolver`の目的関数へトグル式の新しい項（またはcheckpoint87以前からの既存項の一般化）として反映した。
  - ①一日当たりの講師人数（少なく/多く/考慮しない）: 従来常時ONだった`TeacherDayConcentrationTerms`をトグル化・改名（`TeacherCountPerDayTerms`）。
  - ②講師ごとのコマ数の偏り（均等にする/考慮しない・新規）: 講師の総コマ数の最大値を最小化するmin-max近似。
  - ③生徒の授業日（減らす/分散する/考慮しない）: 従来常時ONだった日程分散（`DayDispersionTerms`、weight 10,000）をトグル化。
  - ④1コマあたりの生徒対応人数（多く/少なく/考慮しない）: 従来常時ONだったペア優遇（`PairingBonusTerms`）を、設定した上限人数（1対N）に応じて一般化・トグル化（`PairingSizeTerms`）。
  - ⑤時間帯（遅く/早く/考慮しない・新規）: コマの時限順（SlotOrder）に比例した加点/減点。
  - ⑥同時に使える座席数（学校全体で同時刻にN人まで/考慮しない・新規）: ハード制約として追加。教室単位ではなく学校全体の合計人数の上限。
- 新規プロジェクト作成時の既定値はすべて「考慮しない」（①②⑤⑥は元々存在しなかった機能なので挙動に影響なし。③④は元々常時ONだった機能が既定でOFFになる、確認済みの仕様変更）。

### 設定の保存場所（プロジェクトの既定値＋実行時の一時上書き）
- 「①設定」に新しい「スケジュール設定」タブを追加し、7項目すべて（比率＋6方針）をプロジェクトの既定値として保存できるようにした（`SchedulingPolicy`テーブル、`ISchedulingPolicyRepository`/`SqliteSchedulingPolicyRepository`、`OutputSetting`と同じ1行/プロジェクトの構成）。
- ⑤時間割自動作成の画面にも「この回だけ探索の方針を変更する」という折りたたみ可能なセクションを追加した。画面を開いた時点ではプロジェクトの既定値を表示し、その場で変更してもプロジェクトの既定値そのものは変わらない（今回の実行にだけ適用される、実行後に破棄される一時的な上書き）。
